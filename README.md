# Skyline Rush — Roblox Simulator / Tycoon

A small Roblox game prototype built with Luau and Rojo. The repository is intended to be cloned and opened by a developer in Roblox Studio; the recruiter does not need this author to run Studio locally.

## MVP features

- Collect energy crystals using Roblox ProximityPrompts (keyboard, gamepad and touch prompt support).
- Carry-capacity limit and crystal exchange station.
- Coins and a speed-upgrade terminal.
- Server-authoritative economy and collection logic.
- HUD for coins, crystals, capacity and upgrade level.
- DataStore persistence with retries and safe handling of load failures.
- Procedurally generated stylized island scene; no external model dependencies.

## Quick start (developer / reviewer)

### Option A — Rojo (recommended)

1. Install Roblox Studio and Rojo 7.5.1 (Aftman configuration is included).
2. Clone this repository.
3. In the project directory run `rojo serve`.
4. Open a new Baseplate in Roblox Studio and connect the Rojo plugin to the running server.
5. Press **Play**. The server script creates the map automatically.

### Option B — Build a place file

```bash
rojo build -o SkylineRush.rbxlx
```

Open `SkylineRush.rbxlx` in Roblox Studio and press **Play**.

## Controls

- Approach an energy crystal and activate its prompt to collect it.
- Use the Energy Exchange pad to sell carried crystals.
- Use the Upgrade Terminal to purchase movement-speed upgrades.

## DataStore testing

DataStore persistence requires a published Roblox experience and API services enabled for the test experience. In Studio, use **Game Settings → Security → Enable Studio Access to API Services** only for a private test experience. The game intentionally kicks a player if their data cannot be loaded after retries, rather than silently overwriting potentially existing data with defaults.

## Architecture

```text
src/
  shared/Config.lua
  server/Main.server.lua
  server/Services/
    PlayerDataService.lua
    WorldService.lua
    GameService.lua
  client/HUD.client.lua
```

- `WorldService` creates the prototype world and collectible resources.
- `GameService` owns server-side game rules and economy.
- `PlayerDataService` loads and saves player progress.
- `HUD.client.lua` renders replicated player stats.

## Visual assets and licensing

The MVP scene uses Roblox-native Parts and materials generated by code, so there are no untracked third-party meshes or texture licensing dependencies. For a later art pass, the project can use Kenney's **Nature Kit** and **Building Kit**, both marked CC0 on the creator's official asset pages:

- https://kenney.nl/assets/nature-kit
- https://kenney.nl/assets/building-kit
- License guidance: https://kenney.nl/support

CC0 means those assets may be used in commercial projects; attribution is not required, though credit is appreciated. Download and import selected models during the art pass, and keep the original license files with the assets.

## Scope and known limitations

This is a playable MVP foundation, not a production-ready commercial release. It still needs an in-engine playtest, mobile/gamepad layout review, economy balancing, onboarding, original art/audio, analytics instrumentation, moderation review, and publication testing. No real player-retention or revenue metrics are claimed.
